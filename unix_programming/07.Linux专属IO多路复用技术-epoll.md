## 一. epoll

### 1.1 epoll概念

epoll是Linux内核提供的一种高效的I/O多路复用机制，它是select和poll的改进版本。

### 1.2 epoll的主要特点

- **高效性**: 使用红黑树存储
- **适用fd** : socket，字符设备（如/dev/random）、管道、timerfd和signalfd
- **事件驱动**:基于注册事件返回对应事件就绪的文件描述符

## 二. epoll编程

### 一、核心结构体

#### 1. `struct epoll_event`

```c
typedef union epoll_data {
    void        *ptr;    // 用户数据指针
    int          fd;     // 文件描述符
    uint32_t     u32;    // 32位整数
    uint64_t     u64;    // 64位整数
} epoll_data_t;

struct epoll_event {
    uint32_t     events;      // epoll 事件类型
    epoll_data_t data;        // 用户数据
};
```

**事件类型：**

- `events`可以是以下值的位或组合：
  - `EPOLLIN`：文件描述符可读
  - `EPOLLOUT`：文件描述符可写
  - `EPOLLET`：边缘触发模式
  - `EPOLLHUP`：挂起
  - `EPOLLRDHUP`：对端关闭连接或半关闭
  - `EPOLLPRI`：紧急数据可读
  - `EPOLLERR`：错误发生
  - `EPOLLONESHOT`：一次性事件

| 事件类型         | 宏定义       | 物理含义             | 典型触发场景                                            |
| :--------------- | :----------- | :------------------- | :------------------------------------------------------ |
| **读事件** | `EPOLLIN`  | **缓冲区有货** | 1. 网卡收到数据存入 buffer`<br>`2. 对方关闭连接 (EOF) |
| **写事件** | `EPOLLOUT` | **缓冲区有坑** | 1. 缓冲区没满`<br>`2. 刚发送完数据，腾出了空间        |

**注意**： **写事件不是“正在写”**：写事件不是说数据正在发送，而是说**你可以往内核拷贝数据了**。

### 二、核心 API 详解

#### 1. `epoll_create`/ `epoll_create1`

```c
#include <sys/epoll.h>

int epoll_create(int size);
int epoll_create1(int flags);
```

**返回值：**

- 成功：返回 epoll 实例的文件描述符（≥0）
- 失败：返回 -1，并设置 errno

**参数说明：**

- `epoll_create(size)`
  - `size`：内核事件表的初始大小（Linux 2.6.8 后忽略，但必须大于0）
- `epoll_create1(flags)`
  - `flags`：创建标志
    - `0`：传统行为
    - `EPOLL_CLOEXEC`：设置 close-on-exec 标志

#### 2. `epoll_ctl`

```c
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
```

**返回值：**

- 成功：返回 0
- 失败：返回 -1，并设置 errno

**参数说明：**

- `epfd`：epoll 实例的文件描述符
- `op`：操作类型：
  - `EPOLL_CTL_ADD`：添加文件描述符到 epoll 实例
  - `EPOLL_CTL_MOD`：修改已注册的文件描述符事件
  - `EPOLL_CTL_DEL`：从 epoll 实例中删除文件描述符
- `fd`：要操作的目标文件描述符
- `event`：指向 `epoll_event`结构的指针

#### 3. `epoll_wait`

```c
int epoll_wait(int epfd, struct epoll_event *events,
               int maxevents, int timeout);
```

**返回值：**

- 成功：返回就绪的文件描述符数量
- 超时：返回 0
- 失败：返回 -1，并设置 errno

**参数说明：**

- `epfd`：epoll 实例的文件描述符
- `events`：用于接收就绪事件的数组
- `maxevents`：events 数组的最大容量
- `timeout`：超时时间（毫秒）
  - `-1`：无限阻塞
  - `0`：立即返回
  - `>0`：等待指定毫秒数



## 三. 边缘触发和水平触发

### 3.1 水平触发(Level Triggered, LT)

**特点**:

- 只要文件描述符处于就绪状态，epoll_wait就会返回该事件

**工作原理**:

```
数据到达 -> 触发事件 -> 应用程序处理部分数据 -> 仍有数据未读 -> 再次触发事件
```

**示例代码**:

```c
// LT模式示例
struct epoll_event event;
event.events = EPOLLIN; // 默认就是LT模式
event.data.fd = fd;
epoll_ctl(epoll_fd, EPOLL_CTL_ADD, fd, &event);

// 在LT模式下，可以只读取部分数据
char buffer[100];
read(fd, buffer, 100); // 即使socket中还有更多数据，下次epoll_wait仍会返回
```

### 3.2 边缘触发(Edge Triggered, ET)

**特点**:

- 只有在文件描述符状态发生变化时才触发事件
- 必须配合非阻塞I/O使用

**工作原理**:

```
数据到达 -> 触发事件 -> 应用程序必须读取所有数据 -> 不再触发，直到新数据到达
```

**示例代码**:

```c
// ET模式示例
struct epoll_event event;
event.events = EPOLLIN | EPOLLET; // 边缘触发
event.data.fd = fd;
epoll_ctl(epoll_fd, EPOLL_CTL_ADD, fd, &event);

// 在ET模式下，必须读取所有可用数据
char buffer[1024];
ssize_t bytes_read;
while ((bytes_read = read(fd, buffer, sizeof(buffer))) > 0) {
    // 处理数据
}
// 必须读到EAGAIN为止
```

**ET 模式下的坑**：
    *   **读**：必须一次性循环读完直到返回 `EAGAIN`，否则下次 epoll_wait 不会通知你，剩下的数据就“死”在缓冲区里了。
    *   **写**：通常不需要监听 `EPOLLOUT`。只有当你 `write()` 返回 `EAGAIN` (缓冲区满了) 时，才需要将 fd 加入 epoll 监听 `EPOLLOUT`。一旦收到 `EPOLLOUT` 通知（说明有空间了），写完数据后应**立即移除** `EPOLLOUT` 监听。

### 3.3 LT vs ET 对比

| 特性               | LT(水平触发)   | ET(边缘触发)   |
| ------------------ | -------------- | -------------- |
| **触发条件** | 状态满足就触发 | 状态变化时触发 |
| **数据处理** | 可分批处理     | 必须一次处理完 |

## 四. epoll基于事件驱动的代码编写逻辑

**编写 epoll 程序的逻辑遵循一个标准的 "Setup -> Loop -> Dispatch" (初始化 -> 循环等待 -> 事件分发) 模式。**

### 核心逻辑步骤(先准备好监听的socket)

1. 创建实例 ：创建一个 epoll 句柄（相当于创建了一个内核中的“事件容器”）。
2. 注册监听 ：将监听 Socket（Server Socket）放入这个容器，只关注“读事件”( EPOLLIN )。
3. 事件循环 ：进入 while(1) 循环，调用 epoll_wait 阻塞等待。
   - **3.1** 处理事件 ：当 epoll_wait 返回时，遍历返回的“就绪列表”。
     - 如果是读事件
       - 如果是监听 Socket ：说明有新连接 ( accept ) -> 将新连接的 FD 设为 非阻塞 -> 注册到 epoll 。
       - 如果是普通 Socket ：说明有数据 ( read ) -> 读取数据处理 -> 如果读到 EOF 则关闭连接。
     - 如果是写事件  ... ...

## 五. 基于epoll的EchoServer

```c
#include <arpa/inet.h>
#include <errno.h>
#include <fcntl.h>
#include <netinet/in.h>
#include <stdarg.h>
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/epoll.h>
#include <sys/socket.h>
#include <unistd.h>
void set_nonblocking(int fd) {
  int flags = fcntl(fd, F_GETFL, 0); // 先获取文件描述符本来的属性
  flags = flags | O_NONBLOCK;        // 再按位或上非阻塞属性
  fcntl(fd, F_SETFL, flags);         // 设置
}
struct connection {
  int sock;
  struct sockaddr_in addr;
};

// 服务端抽象结构体
struct server {
  int (*make_listener)(const char *, int);
  struct connection (*accept_connection)(int);
  int (*echo)(int, void (*)(int, void *), void *);
  void (*poll)(int);
};
int make_listener(const char *ip, int port) {
  // 1.创建socket
  int listen_sock = socket(AF_INET, SOCK_STREAM, 0);
  if (listen_sock == -1) {
    perror("socket");
    return -1;
  }
  // 2.构造地址结构体
  struct sockaddr_in addr;
  addr.sin_family = AF_INET;
  addr.sin_addr.s_addr = inet_addr(ip);
  addr.sin_port = htons(port);
  // 3.绑定
  if (bind(listen_sock, (struct sockaddr *)&addr, sizeof(addr)) == -1) {
    perror("bind");
    close(listen_sock);
    return -1;
  }
  // 4.监听
  if (listen(listen_sock, 5) == -1) {
    perror("listen");
    close(listen_sock);
    return -1;
  }
  return listen_sock;
}

struct connection accept_connection(int listen_sock) {
  struct connection conn;
  conn.sock = -1;
  // 第二阶段 连接建立
  socklen_t addr_len = sizeof(conn.addr);
  int sock = accept(listen_sock, (struct sockaddr *)&conn.addr, &addr_len);
  if (sock == -1) {
    perror("accept");
    return conn;
  }
  conn.sock = sock;
  printf("Client connected: %s:%d\n", inet_ntoa(conn.addr.sin_addr),
         ntohs(conn.addr.sin_port));
  return conn;
}

int echo(int sock, void (*__callback)(int, void *args), void *args) {
  char buffer[1024];
  ssize_t bytes_received = recv(sock, buffer, sizeof(buffer), 0);
  if (bytes_received == -1) {
    perror("recv");
    close(sock);
    return -1;
  }

  if (bytes_received == 0) {
    if (__callback != NULL) {
      __callback(sock, args);
    } else {
      close(sock);
    }
    return 0;
  }

  buffer[bytes_received] = '\0'; // 确保字符串以null结尾
  printf("Received from client: %s\n", buffer);
  int bytes_sended = send(sock, buffer, bytes_received, 0);
  if (bytes_sended == -1) {
    perror("send");
    close(sock);
    return -1;
  }

  if (bytes_sended == 0) {
    if (__callback != NULL) {
      __callback(sock, args);
    } else {
      close(sock);
    }
    return 0;
  }
  return 1;
}

// ET模式的echo
int echo_et(int sock, void (*__callback)(int, void *args), void *args) {
  char buffer[1024];
  ssize_t bytes_received;
  while (1) {
    // ET模式：必须循环读取直到EAGAIN
    while (1) {
      bytes_received = recv(sock, buffer, sizeof(buffer), 0);

      // 读取错误处理
      if (bytes_received == -1) {
        if (errno == EAGAIN || errno == EWOULDBLOCK) {
          // 数据读完了，正常退出
          break;
        } else {
          perror("recv");
          close(sock);
          return -1;
        }
      }
      // 客户端关闭连接处理
      if (bytes_received == 0) {
        if (__callback != NULL) {
          __callback(sock, args);
        } else {
          close(sock);
        }
        return 0;
      }
    }
    // 处理读取到的数据
    buffer[bytes_received] = '\0';
    printf("Received from client: %s\n", buffer);
    int bytes_sended = send(sock, buffer, bytes_received, 0);
    //处理错误
    if (bytes_sended == -1) {
      perror("send");
      close(sock);
      return -1;
    }
    // 处理关闭连接
    if (bytes_sended == 0) {
      if (__callback != NULL) {
        __callback(sock, args);
      } else {
        close(sock);
      }
      return 0;
    }
  }
}

// 回显回调函数参数结构体
struct cbargs {
  int epoll; // epoll实例
};
void handle_cb(int sock, void *args) {
  struct cbargs *cbargs = (struct cbargs *)args;
  epoll_ctl(cbargs->epoll, EPOLL_CTL_DEL, sock, NULL);
  close(sock);
}

void poll(int listen_sock) {
  // 创建epoll实例
  int epoll = epoll_create1(0);

  // 构造监听socket的epoll事件结构体
  struct epoll_event listensock_event = {.data.fd = listen_sock,
                                         .events = EPOLLIN};
  // 将监听socket加入红黑树
  epoll_ctl(epoll, EPOLL_CTL_ADD, listen_sock, &listensock_event);

  // 主事件循环
  while (1) {
    // 创建epoll事件结构体数组
    struct epoll_event events[1024];
    // 调用epoll_wait等待事件
    int num = epoll_wait(epoll, events, 1024, 1000);
    if (num < 0) {
      perror("epoll_wait");
      close(listen_sock);
      break;
    }
    if (num == 0) {
      // printf("epoll_wait timeout!!!!");
      continue;
    } else {
      for (int i = 0; i < num; ++i) {
        if (events[i].events & EPOLLIN) {
          // 处理读事件
          //  如果是监听socket,处理新连接
          // 否则处理客户端连接
          if (events[i].data.fd == listen_sock) {
            // 接受新连接
            struct connection conn = accept_connection(listen_sock);
            if (conn.sock == -1) {
              printf("connection failed!!!\n");
              continue;
            }
            set_nonblocking(conn.sock); // 设置非阻塞io
            printf("server connect client :%s:%d\n",
                   inet_ntoa(conn.addr.sin_addr), conn.addr.sin_port);
            // 构造epoll事件结构体,注册读事件，默认LT
            struct epoll_event event = {.data.fd = conn.sock,
                                        .events = EPOLLIN};

            // 构造epoll事件结构体,注册读事件，ET模式
            // struct epoll_event event = {.data.fd = conn.sock,.events =
            // EPOLLIN | EPOLLET};

            // 为测试LT和ET区别，构造epoll事件结构体,注册写事件，默认LT模式
            // struct epoll_event event = {.data.fd = conn.sock,.events =
            // EPOLLOUT };

            // 为测试LT和ET区别，构造epoll事件结构体,注册写事件,ET模式
            // struct epoll_event event = {.data.fd = conn.sock,.events =
            // EPOLLOUT | EPOLLET};

            //  添加到红黑树
            epoll_ctl(epoll, EPOLL_CTL_ADD, conn.sock, &event);
            continue;
          } else {
            struct cbargs args = {.epoll = epoll};
            // 默认LT模式的echo
            int res = echo(events[i].data.fd, handle_cb, &args);

            // et模式的echo
            //  int res = echo_et(events[i].data.fd, handle_cb, &args);

            if (res <= 0)
              break;
          }
        } else if (events[i].events & EPOLLOUT) {
          // 处理写事件
          printf("EPOLLOUT handles\n");
          continue;
        } else {
          printf("unknown event");
          continue;
        }
      }
    }
  }
  close(epoll);
}
// 工厂函数
struct server make_server() {
  struct server server = {
      .make_listener = make_listener,
      .accept_connection = accept_connection,
      .echo = echo,
      .poll = poll,
  };
  return server;
}

int main() {
  struct server server = make_server();
  int listen_socket = server.make_listener("127.0.0.1", 8080);
  if (listen_socket < 0) {
    exit(-1);
  }
  server.poll(listen_socket);
  close(listen_socket);
  return 0;
}
```

## 六. epoll的底层原理

### 1. 核心数据结构

**1. `struct eventpoll` (epoll 实例)**
这是 epoll 的“大脑”，对应 `epoll_create` 创建的 epoll 文件描述符。
```c
struct eventpoll {
    // 互斥锁，保护内核态的内部数据
    struct mutex mtx;
    // 等待队列，存放调用 epoll_wait() 进入等待的进程
    wait_queue_head_t wq;
    // poll 等待队列，用于 epollfd 本身被 poll 的情况
    wait_queue_head_t poll_wait;
    // 就绪链表 (Ready List)，存放所有已经就绪的 epitem
    struct list_head rdllist;
    // 自旋锁，保护 rdllist
    rwlock_t lock;
    // 红黑树根节点，管理所有被监听的文件描述符 (epitem)
    struct rb_root_cached rbr;
    // ... 其他成员
};
```
- 等待队列wq，存放调用 epoll_wait() 进入等待的进程
- 等待队列poll_wait，用于 epollfd 本身被 poll 的情况
- 就绪链表rdllist，存放所有已经就绪的 epitem
- 红黑树根节点rbr，管理所有被监听的文件描述符 (epitem)


**2. `struct epitem` (监控项)**
每个被监控的文件描述符都对应一个 `epitem` 结构。
```c
struct epitem {
    // 红黑树节点，连接到 eventpoll->rbr
    union {
        struct rb_node rbn;
        struct rcu_head rcu;
    };
    // 链表节点，当事件就绪时，链接到 eventpoll->rdllist
    struct list_head rdllink;
    // 指向所属的 eventpoll 对象
    struct eventpoll *ep;
    // 包含被监控的 fd 和 file 指针
    struct epoll_filefd ffd;
    // 用户关心的事件掩码 (如 EPOLLIN, EPOLLOUT)
    struct epoll_event event;
    // ...
};
```
重要成员：
- 红黑树节点
- 就绪队列
- eventpoll指针
- 被监控的fd
- epoll事件
### 2. 三个核心 API 的底层原理

#### 1. `epoll_create` (创建)
*   **系统调用**：`sys_epoll_create1`
*   **核心逻辑**：
    1.  在内核中分配一个 `struct eventpoll` 对象。
    2.  初始化红黑树根节点 (`rbr`)、就绪链表 (`rdllist`)、等待队列 (`wq`) 等。
    3.  创建一个匿名文件 (`anon_inode`)，将 `file->private_data` 指向这个 `eventpoll` 对象。
    4.  返回这个匿名文件的 fd。

#### 2. `epoll_ctl` (控制)
*   **系统调用**：`sys_epoll_ctl`
*   **核心逻辑**：
	* `EPOLL_CTL_ADD`: 调用`ep_insert`
		1.  **分配 epitem**：为要添加的 fd 创建一个 `epitem` 对象。
	    2.  **插入红黑树**：将 `epitem` 插入到 `eventpoll` 的红黑树中，方便后续查找和去重。
	    3.  **注册回调 (关键)**：
        *   调用目标文件（如 socket）的 `poll` 接口（内核驱动的poll接口，功能是报告单个特定设备/文件的当前状态，并挂载等待队列）。
        *   在 `poll` 实现中，会调用 `poll_wait`，最终执行 epoll 注册的 `ep_ptable_queue_proc` 函数。
        *   `ep_ptable_queue_proc` 会分配一个等待队列项 (`struct eppoll_entry`)，并将回调函数设置为 **`ep_poll_callback`**。
        *   **结果**：将 epoll 的“探针”插入到了目标文件的等待队列中。一旦目标文件状态改变（如数据到达），就会调用 `ep_poll_callback`。
		4.  **初次检查**：如果注册时文件已经就绪，直接将其加入 `rdllist`。
	- `EPOLL_CTL_DEL`: 调用 `ep_remove`，从红黑树移除，并注销等待队列中的回调。
    - `EPOLL_CTL_MOD`: 修改 `epitem` 中的事件掩码。  
  
#### 3. `epoll_wait` (等待)
*   **系统调用**：`sys_epoll_wait` -> `ep_poll`
*   **核心逻辑**：
    1.  **检查就绪链表**：查看 `eventpoll->rdllist` 是否为空。
    2.  **睡眠等待**：
        *   如果 `rdllist` 为空且未超时，当前进程将自己添加到 `eventpoll->wq` 等待队列中。
        *   设置进程状态为 `TASK_INTERRUPTIBLE` 并让出 CPU。
    3.  **被唤醒**：
        *   当有事件发生，`ep_poll_callback` 会被调用，它会将对应的 `epitem` 挂入 `rdllist`，并唤醒 `wq` 中的等待进程。
    4.  **传输数据**：
        *   进程被唤醒后，调用 `ep_send_events`。
        *   遍历 `rdllist`，将就绪事件拷贝到用户态内存 (`events` 数组)。
        *   如果是 **ET (Edge Trigger)** 模式，事件被处理后可能不再重新加入就绪列表；如果是 **LT (Level Trigger)** 模式且事件未处理完，会再次加入。

### 3. 完整流程

**核心机制：回调通知 + 就绪列表**

1.  **建立连接 (Setup)**：
    用户调用 `epoll_ctl` 添加 fd。内核通过 `f_op->poll` 钩子，在目标设备（如网卡驱动、Socket）的等待队列上注册了一个回调函数 `ep_poll_callback`。

2.  **数据到达 (Interrupt)**：
    当网络数据包到达网卡，硬件中断触发驱动程序处理。驱动程序将数据拷贝到内核缓冲区，然后唤醒（wake_up）等待在该 Socket 上的队列。

3.  **触发回调 (Callback)**：
    唤醒操作触发了之前注册的 `ep_poll_callback`。
    *   **`ep_poll_callback` 做了什么？**
        1.  根据等待队列项找到对应的 `epitem`。
        2.  将这个 `epitem` 添加到 epoll 实例的 **就绪链表 (`rdllist`)** 尾部。
        3.  检查是否有进程阻塞在 `epoll_wait`（即检查 `eventpoll->wq`），如果有，就唤醒该进程。

4.  **收割事件 (Harvest)**：
    用户进程从 `epoll_wait` 阻塞中苏醒（或者原本就没睡），发现 `rdllist` 不为空。它将链表中的事件复制到用户空间，并清空（或部分保留，视 LT/ET 而定）链表。


### 4. epoll实例的管理

**epoll实例的管理本质是基于文件系统的管理**
##### 1. 是谁管理？（文件描述符与核心对象）

epoll 实例本质上是由 **`anon_inode`（匿名 inode）文件系统** 管理的一个文件对象。

*   **用户态视角**：通过一个普通的 **文件描述符 (fd)** 来管理。
*   **内核态视角**：
    *   该 fd 对应一个 `struct file` 对象。
    *   该 `struct file` 的 `private_data` 指针，指向了 epoll 的核心数据结构 **`struct eventpoll`**。

 **file结构体关键部分**
```c
struct file {
    struct path     f_path;      // 包含 dentry 和 vfsmount，指明文件路径
    struct inode    *f_inode;    // 指向对应的 inode (缓存值)
    const struct file_operations *f_op; // 【关键】操作函数表
                                        // 决定了 read/write/poll 具体执行什么代码
                                        // 对于 epoll，这里指向 eventpoll_fops
    atomic_long_t   f_count;     // 引用计数。dup() 或 fork() 会增加它
    void            *private_data; // 【核心】私有数据指针
                                   // 不同的驱动或文件系统用它存自己的状态
                                   // 对于 epoll，这里存放 struct eventpoll 指针
#ifdef CONFIG_EPOLL
    /* Used by fs/eventpoll.c to link all the hooks to this file */
    struct hlist_head *f_ep;     // 【反向映射】
                                 // 这是一个链表头，记录了“有哪些 epoll 实例正在监听我”
                                 // 当这个文件关闭时，内核遍历这个链表，
                                 // 把自己从所有监听它的 epoll 实例中移除。
#endif
};
```

**在 `do_epoll_create` 函数中（`epoll_create` 的核心实现）：**
```c
// fs/eventpoll.c : 1987
static int do_epoll_create(int flags)
{
    // ...
    // 1. 分配核心结构体 struct eventpoll
    error = ep_alloc(&ep);
    
    // 2. 获取一个未使用的文件描述符 fd
    fd = get_unused_fd_flags(O_RDWR | (flags & O_CLOEXEC));
    
    // 3. 关键点：创建一个匿名文件
    // "[eventpoll]" 是名字
    // &eventpoll_fops 是操作接口
    // ep 是私有数据 (private_data)
    file = anon_inode_getfile("[eventpoll]", &eventpoll_fops, ep,
                 O_RDWR | (flags & O_CLOEXEC));
    
    // 4. 将 file 和 ep 互相关联
    ep->file = file;
    
    // 5. 将 fd 和 file 关联，安装到当前进程的 fd 表中
    fd_install(fd, file);
    return fd;
}
```

##### 2. 通过什么接口管理？（`file_operations`）

既然 epoll 是一个文件，它就必须实现 VFS（虚拟文件系统）的标准接口 `struct file_operations`。

epoll 定义了自己的操作集 **`eventpoll_fops`**，这决定了我们可以对 epoll fd 做哪些操作（比如 `close`, `poll` 等）。

```c
// fs/eventpoll.c : 889
static const struct file_operations eventpoll_fops = {
#ifdef CONFIG_PROC_FS
    .show_fdinfo    = ep_show_fdinfo,      // cat /proc/pid/fdinfo/epfd 时调用
#endif
    .release    = ep_eventpoll_release,    // close(epfd) 时调用，负责资源回收
    .poll       = ep_eventpoll_poll,       // 当 epfd 被嵌套监听时调用
    .llseek     = noop_llseek,             // 不支持 seek
};
```

注意：`epoll_ctl` 和 `epoll_wait` 并没有直接使用 `file_operations` 里的函数，而是通过系统调用直接操作 `struct file` 里的 `private_data`（即 `struct eventpoll`）。

##### 3. 怎么管理？（生命周期管理）

整个管理流程依赖于引用计数和 VFS 机制：

1.  **创建 (Create)**：
    *   调用 `epoll_create` -> `anon_inode_getfile`。
    *   内核在内存中分配一个 `struct inode`（匿名）和一个 `struct file`。
    *   `struct eventpoll` 被挂载到 `file->private_data` 上。

2.  **使用 (Use)**：
    *   当你调用 `epoll_ctl(epfd, ...)` 时，内核通过 `fdget(epfd)` 找到对应的 `struct file`。
    *   然后通过 `file->private_data` 取出 `struct eventpoll` 对象进行操作（如插入红黑树）。

3.  **销毁 (Destroy)**：
    *   当你调用 `close(epfd)` 时，`struct file` 的引用计数减 1。
    *   当引用计数归零时，VFS 自动调用 `eventpoll_fops.release`，即 **`ep_eventpoll_release`**。
    *   `ep_eventpoll_release` 会释放红黑树中的所有节点，释放 `struct eventpoll` 内存，完成清理。


## 七. epoll和poll

| 特性                 | epoll              | poll      |
| -------------------- | ------------------ | --------- |
| **数据结构**   | 红黑树             | 数组      |
| **时间复杂度** | O(1)               | O(n)      |
| **触发模式**   | 支持ET和LT         | 仅支持LT  |
| **跨平台性**   | Linux专有          | POSIX标准 |
| **适用场景**   | 大量连接，少量活跃 | 少量连接  |

### Epoll 为什么高效？

1.  **O(1) 的就绪检测**：利用 `rdllist`，进程不需要遍历所有监控的 fd，只处理发生的事件。
2.  **回调机制**：利用内核等待队列机制，被动接收通知，而不是主动轮询。
3.  **红黑树管理**：在大规模并发下，fd 的增删改查效率稳定在 O(logN)。
