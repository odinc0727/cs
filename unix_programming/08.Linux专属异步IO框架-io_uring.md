## 一. io_uring简介

io_uring 是 Linux 内核 5.1 引入的一个高性能异步 I/O 框架。它旨在解决旧有 AIO 的诸多限制（如仅支持 Direct I/O、系统调用开销大、内存拷贝多等），提供一个统一、高效的异步 I/O 接口。

- 可参考文档：https://arthurchiao.art/blog/intro-to-io-uring-zh/
- liburing库地址 ：https://github.com/axboe/liburing

**真正的异步 I/O ：支持 Buffered I/O 和 Direct I/O，不仅限于磁盘 I/O，还完全支持网络 I/O**

**tips**

| 特性          | Direct I/O                     | Buffered I/O                             |
| ------------- | ------------------------------ | ---------------------------------------- |
| **缓存机制**​ | 绕过内核页缓存，直接与磁盘交互 | 使用内核页缓存，数据先写入缓存再异步刷盘 |

- **同步**：程序执行一个任务时，必须等待这个任务完全完成后才能继续执行下一个任务
- **异步**：程序可以启动一个任务，然后不等待它完成就继续执行其他任务，当任务完成时会通过某种方式通知程序。**我们可以把异步想象成两步，提交任务/请求 和 获取任务执行/请求执行结果**



## 二. io_uring基本了解

**io_uring是异步机制，本质可以抽象成两个动作，提交异步请求和获取异步结果**

### 1. 核心组件

io_uring 的核心是两个基于共享内存的环形队列：

- SQ (Submission Queue) ：提交队列。用户态程序将 I/O 请求（SQE - Submission Queue Entry）写入此队列，通知内核处理。
- CQ (Completion Queue) ：完成队列。内核将处理完成的结果（CQE - Completion Queue Entry）写入此队列，用户态程序从中读取结果。

### 2. 三个系统调用

1. `io_uring_setup`：初始化一个 io_uring 实例。分配 SQ 和 CQ 的内存，配置队列大小和标志位，返回一个文件描述符 (fd)。
2. `io_uring_enter`：核心入口。用于提交 SQ 中的请求给内核，和/或 等待 CQ 中产生完成事件。可以同时进行“提交”和“等待”。
3. `io_uring_register` ：注册长期使用的资源（如文件描述符、缓冲区）。注册后，内核可以建立索引，避免每次 I/O 都进行文件查找和页表映射，显著降低开销。

### 3. io_uring的工作模式

#### 1. 中断模式

**特点**：

- 默认模式，当I/O操作完成时通过中断通知
- 适合低延迟要求的应用
- CPU使用率相对较低

#### 2. 轮询模式

**IORING_SETUP_IOPOLL**：

```c
struct io_uring ring;
io_uring_queue_init(QUEUE_DEPTH, &ring, IORING_SETUP_IOPOLL);
```

**特点**：

- 需要文件系统和和块设备支持轮询功能
- 内核持续轮询I/O完成状态
- 减少中断开销，提供更低的延迟
- 消耗更多CPU资源

#### 3. 内核轮询模式

**IORING_SETUP_SQPOLL**：

```c
struct io_uring ring;
io_uring_queue_init(QUEUE_DEPTH, &ring, IORING_SETUP_SQPOLL);
```

**特点**：

- 内核线程持续轮询提交队列
- 减少用户空间到内核空间的切换
- 用户空间提交请求后无需系统调用
- 需要额外的内核线程资源

## 三. io_uring编程（`liburing.h`）

**我们编程是用liburing库编程**

### 1、 核心结构体

#### 1. `struct io_uring`

这是 `liburing` 的核心句柄，用于管理整个 io_uring 实例（包括提交队列 SQ 和完成队列 CQ）。

```c
struct io_uring {
    struct io_uring_sq sq; // 提交队列 (Submission Queue)
    struct io_uring_cq cq; // 完成队列 (Completion Queue)
    unsigned flags;
    int ring_fd;           // 内核 io_uring 的文件描述符
    // ... 其他内部成员
};
```

- **功能**: 保存 io_uring 实例的上下文信息。用户代码通常只需要定义一个 `struct io_uring` 变量，并将其指针传给 API 函数即可，不需要直接操作其内部成员。

#### 2. `struct io_uring_sqe`

提交队列项，描述一个具体的 I/O 请求。

```c
struct io_uring_sqe {
    __u8    opcode;         // 操作码 (如 IORING_OP_READ, IORING_OP_ACCEPT)
    __u8    flags;          // 标志位 (如 IOSQE_FIXED_FILE)
    __u16   ioprio;         // 优先级
    __s32   fd;             // 要操作的文件描述符
    __u64   off;            // 偏移量
    __u64   addr;           // 缓冲区地址 或 结构体指针
    __u32   len;            // 数据长度
    union {
        __kernel_rwf_t  rw_flags;
        __u32           fsync_flags;
        // ...
    };
    __u64   user_data;      // 用户自定义数据，用于在 CQE 中找回上下文
    // ... padding
};
```

- **功能**: 包含了执行一个 I/O 操作所需的所有参数（Opcode, FD, Buffer, Length, Offset 等）。
- **关键点**: `user_data` 字段非常重要，它会原样复制到对应的 CQE 中，通常用于存放回调函数指针或请求上下文 ID。

#### 3. `struct io_uring_cqe

完成队列项，描述一个 I/O 请求的执行结果。

```c
struct io_uring_cqe {
    __u64   user_data;      // 对应 SQE 中设置的 user_data
    __s32   res;            // 操作结果 (类似 syscall 的返回值，如读取字节数或 -errno)
    __u32   flags;          // 标志位
};
```

- **功能**: 承载 I/O 操作的返回结果。
- **关键点**:
     - `res`: 如果 `>= 0`，通常表示成功（如 `read` 读到的字节数）；如果 `< 0`，则是错误码（如 `-EAGAIN`, `-EINVAL`）。
     - `user_data`: 用来识别这个结果对应之前提交的哪个请求。

### 2、 基本API

#### 1. 初始化

**函数**: `io_uring_queue_init`

```c
int io_uring_queue_init(unsigned entries, struct io_uring *ring, unsigned flags);
```

- **功能**: 初始化一个新的 io_uring 实例，映射内核环形缓冲区到用户空间。
- **返回值**: 成功返回 `0`；失败返回负的错误码（如 `-ENOMEM`）。
- **参数**:
     - `entries`: 队列深度（必须是 2 的幂，如 1024, 4096）。决定了同一时刻能 pending 的最大请求数。
     - `ring`: 指向用户定义的 `struct io_uring` 实例的指针。
     - `flags`: 标志位，通常为 `0`。常用标志如 `IORING_SETUP_SQPOLL` (启用内核轮询线程以减少系统调用开销)。

#### 2. 获取 SQE

**函数**: `io_uring_get_sqe`

```c
struct io_uring_sqe *io_uring_get_sqe(struct io_uring *ring);
```

- **功能**: 从提交队列（SQ）中获取一个空闲的 SQE 指针，用于填充新的 I/O 请求。
- **返回值**: 成功返回指向 SQE 的指针；如果 SQ 已满，返回 `NULL`。
- **参数**:
     - `ring`: io_uring 实例指针。
- **注意**: 如果返回 `NULL`，说明队列满了，通常需要先调用 `io_uring_submit` 提交现有请求，或者等待 CQE 消费来释放空间。

#### 3. 接受连接

**函数**: `io_uring_prep_accept`

```c
void io_uring_prep_accept(struct io_uring_sqe *sqe, int fd, struct sockaddr *addr, socklen_t *addrlen, int flags);
```

- **功能**: 准备一个 accept 请求（对应 `accept4` 系统调用）。
- **返回值**: 无（`void`）。
- **参数**:
     - `sqe`: 通过 `io_uring_get_sqe` 获取的 SQE 指针。
     - `fd`: 监听 socket 的文件描述符。
     - `addr`: 指向客户端地址结构的指针。
     - `addrlen`: 指向地址长度变量的指针。
     - `flags`: accept 标志，如 `SOCK_NONBLOCK`。

#### 4. 发起连接

**函数**: `io_uring_prep_connect`

```c
void io_uring_prep_connect(struct io_uring_sqe *sqe, int fd, const struct sockaddr *addr, socklen_t addrlen);
```

- **功能**: 准备一个 connect 请求（对应 `connect` 系统调用）。
- **返回值**: 无。
- **参数**:
     - `sqe`: SQE 指针。
     - `fd`: 客户端 socket 的文件描述符。
     - `addr`: 目标服务器地址。
     - `addrlen`: 地址长度。

### 5.打开

**函数**: `io_uring_prep_openat`

```c
void io_uring_prep_openat(struct io_uring_sqe *sqe, int dfd, const char *path, int flags, mode_t 
mode);
```

- **功能** : 准备一个异步打开或创建文件的请求（对应 openat 系统调用）。
- **参数 **:
     - sqe : SQE 指针。
     - dfd : 目录文件描述符。通常使用 AT_FDCWD 表示当前工作目录；如果 path 是相对路径且 dfd 是有效的目录 FD，则相对于该目录解析。
     - path : 要打开的文件路径字符串。 注意 ：该字符串内存必须在请求完成前保持有效（不能是栈上的临时变量）。
     - flags : 打开标志位（如 O_RDWR , O_CREAT , O_DIRECT 等）。
     - mode : 文件权限模式（如 0644 ）。仅当 flags 包含 O_CREAT 或 O_TMPFILE 时有效，否则忽略。vv

#### 6. 读

**函数**: `io_uring_prep_read`

```c
void io_uring_prep_read(struct io_uring_sqe *sqe, int fd, void *buf, unsigned nbytes, __u64 offset);
```

- **功能**: 准备一个读请求（对应 `read` 或 `pread`）。
- **返回值**: 无。
- **参数**:
     - `sqe`: SQE 指针。
     - `fd`: 文件描述符。
     - `buf`: 接收数据的缓冲区。
     - `nbytes`: 要读取的字节数。
     - `offset`: 文件偏移量。对于 socket 或不支持 offset 的设备，设为 0 或 -1。

#### 7. 写

**函数**: `io_uring_prep_write`

```c
void io_uring_prep_write(struct io_uring_sqe *sqe, int fd, const void *buf, unsigned nbytes, __u64 offset);
```

- **功能**: 准备一个写请求（对应 `write` 或 `pwrite`）。
- **返回值**: 无。
- **参数**:
     - `sqe`: SQE 指针。
     - `fd`: 文件描述符。
     - `buf`: 发送数据的缓冲区。
     - `nbytes`: 要写入的字节数。
     - `offset`: 文件偏移量。

#### 8. 设置 User Data

**函数**: `io_uring_sqe_set_data` (通常是内联函数或宏)

```c
void io_uring_sqe_set_data(struct io_uring_sqe *sqe, void *data);
```

- **功能**: 设置 SQE 的 `user_data` 字段。这个值会在请求完成时原封不动地出现在 CQE 的 `user_data` 字段中。
- **返回值**: 无。
- **参数**:
     - `sqe`: SQE 指针。
     - `data`: 用户数据指针。通常用来传递自定义结构体指针，该结构体包含识别请求所需的信息（如 fd, buffer, 状态机等）。

#### 9. 提交请求

**函数**: `io_uring_submit`

```c
int io_uring_submit(struct io_uring *ring);
```

- **功能**: 将 SQ 环中所有准备好的 SQE 提交给内核。这会触发一次系统调用（`io_uring_enter`）。
- **返回值**: 成功时返回提交的 SQE 数量；失败返回负的错误码。
- **参数**:
     - `ring`: io_uring 实例指针。

#### 10. 阻塞获取结果

**函数**: `io_uring_wait_cqe`

```c
int io_uring_wait_cqe(struct io_uring *ring, struct io_uring_cqe **cqe_ptr);
```

- **功能**: 等待至少一个完成事件（CQE）到达。如果当前 CQ 为空，线程会进入睡眠状态直到有事件完成。
- **返回值**: 成功返回 `0`；失败返回负的错误码。
- **参数**:
     - `ring`: io_uring 实例指针。
     - `cqe_ptr`: 输出参数。指向一个 `struct io_uring_cqe *` 变量的地址。函数成功返回后，`*cqe_ptr` 将指向队列中的第一个 CQE。

#### 11. 非阻塞获取结果

**函数**: `io_uring_peek_cqe`

```c
int io_uring_peek_cqe(struct io_uring *ring, struct io_uring_cqe **cqe_ptr);
```

- **功能**: 检查 CQ 中是否有已完成的事件。如果不为空，立即返回；如果为空，立即返回错误，**不阻塞**。
- **返回值**:
     - `0`: 成功获取到 CQE。
     - `-EAGAIN`: 队列为空，没有已完成的事件。
     - 其他负值: 发生错误。
- **参数**:
     - `ring`: io_uring 实例指针。
     - `cqe_ptr`: 输出参数，指向获取到的 CQE。

#### 12. 标记结果已处理

**函数**: `io_uring_cqe_seen`

```c
void io_uring_cqe_seen(struct io_uring *ring, struct io_uring_cqe *cqe);
```

- **功能**: 标记该 CQE 已经被用户处理完毕，内核可以重用该 CQE 的槽位。**必须**在处理完 CQE 后调用，否则 CQ 队列会满，导致新的完成事件无法推入。
- **返回值**: 无。
- **参数**:
     - `ring`: io_uring 实例指针。
     - `cqe`: 刚才获取并处理完的 CQE 指针。

#### 13. 销毁

**函数**: `io_uring_queue_exit`

```c
void io_uring_queue_exit(struct io_uring *ring);
```

- **功能**: 拆除 io_uring 实例，释放内存映射，关闭内部的文件描述符。
- **返回值**: 无。
- **参数**:
     - `ring`: io_uring 实例指针。

### 3. io_uring代码编码模式

**io_uring是异步机制，本质可以抽象成两个动作，提交异步请求和获取异步结果**

1. **初始化io_uring**

      ```c
      struct io_uring ring;
      io_uring_queue_init(QUEUE_DEPTH, &ring, 0);
      ```

2. **准备I/O操作**
      - 获取sqe
      - 准备请求
      - 设置需要保存传递的用户数据(可选择)

      ```c
      struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
      io_uring_prep_read(sqe, fd, buffer, size, offset);
      sqe->user_data = request_id;  // 设置用户数据
      ```

3. **提交请求**

      ```c
      io_uring_submit(&ring);
      ```

4. **等待和处理完成**
      - 定义一个cqe结构体指针(如果多个cqe就是结构体指针数组)
      - 阻塞活非阻塞获取结果
      - 标记已处理

      ```c
      struct io_uring_cqe *cqe;
      io_uring_wait_cqe(&ring, &cqe);

      // 处理结果
      printf("Operation %llu completed with result %d\n", cqe->user_data, cqe->res);
      io_uring_cqe_seen(&ring, cqe);
      ```

5. **清理资源**
      ```c
      io_uring_queue_exit(&ring);
      ```

- **_步骤2和3 等同于构造并提交请求_
- **步骤4就等同于获取结果**

### 四. 代码示例

#### 打开并读取文件

```c
#include <arpa/inet.h>
#include <liburing.h>
#include <netinet/in.h>
#include <stdbool.h>
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>
#include<fcntl.h>
#define QUEUE_DEPTH  512
#define BUFFER_SIZE 1024
// 事件类型
enum EventType {OPEN, READ, WRITE };

//将io_uring异步打开文件的操作封装成一个同步函数
int open_file(struct io_uring *ring) {
 //step2: 准备请求
  //1. 获取一个提交队列项
  struct io_uring_sqe *sqe = io_uring_get_sqe(ring);
  if(!sqe){
    perror("io_uring_get_sqe");
    return -1;
  }
  //2. 准备一个打开文件的请求
  const char *filepath = "../test.txt";
  io_uring_prep_openat(sqe, AT_FDCWD, filepath, O_RDWR, 0);
  //3. 设置用户数据为事件类型
  io_uring_sqe_set_data(sqe, (void *)OPEN);


  //step3: 提交请求
  if(io_uring_submit(ring) < 0) {
    perror("io_uring_submit");
     return -1;
  }

  //step4: 等待和处理完成事件
  //1.定义完成队列项指针
  struct io_uring_cqe *cqe;
  //3.阻塞等待完成事件
  if(io_uring_wait_cqe(ring, &cqe) < 0){
    perror("io_uring_wait_cqe");
    return -1;
  }

  int fd;
  //3.处理完成事件
  if((enum EventType)cqe->user_data == OPEN) {
    //打开文件完成事件
    fd = cqe->res;
    if(fd < 0) {
      fprintf(stderr, "Failed to open file: %s\n", strerror(-fd));
       return -1;
    }
    printf("File opened successfully with fd: %d\n", fd);
  }
  //4.标记完成事件已处理
  io_uring_cqe_seen(ring, cqe);
  return fd;
}
//将io_uring异步读取文件的操作封装成一个同步函数
int read_file(struct io_uring *ring,int fd){
  //step2: 准备请求
  //1. 获取一个提交队列项
  struct io_uring_sqe *sqe = io_uring_get_sqe(ring);
  if(!sqe){
    perror("io_uring_get_sqe");
    return 0;
  }

  char buffer[BUFFER_SIZE];

  //2. 准备一个读取文件的请求
  io_uring_prep_read(sqe,fd,buffer,BUFFER_SIZE,0);
  //3. 设置用户数据为事件类型
  io_uring_sqe_set_data(sqe, (void *)READ);
  if(io_uring_submit(ring) < 0) {
    perror("io_uring_submit");
     return 0;
  }
  //step4: 等待和处理完成事件
  //1.定义完成队列项指针
  struct io_uring_cqe *cqe;
  //3.阻塞等待完成事件
  if(io_uring_wait_cqe(ring, &cqe) < 0){
    perror("io_uring_wait_cqe");
    return 0;
  }

  //3.处理完成事件
  if((enum EventType)cqe->user_data == READ) {
    //打开文件完成事件
    int num = cqe->res;
    if(num < 0) {
      fprintf(stderr, "Failed to read file: %s\n", strerror(-fd));
       return 0;
    }
    printf("Read %d bytes: %.*s\n", num, num, buffer);
  }
  //4.标记完成事件已处理
  io_uring_cqe_seen(ring, cqe);
  return 1;
}


int sync_demo(){
//step1: 初始化io_uring
  struct io_uring ring;
  if(io_uring_queue_init(QUEUE_DEPTH, &ring, 0) < 0) {
    perror("io_uring_queue_init");
    return 1;
  }

 int fd = open_file(&ring);
  if(fd < 0){
    fprintf(stderr, "open_file failed\n");
    return 1;
  }

  if(!read_file(&ring,fd)){
    fprintf(stderr, "read_file failed\n");
    return 1;
  }

  //step5: 清理和退出
  io_uring_queue_exit(&ring);
  close(fd);
  return 0;
}

int main() {
  sync_demo();
  return 0;
}
```

#### 异步TCP服务器

```c
#include <arpa/inet.h>
#include <liburing.h>
#include <netinet/in.h>
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>
#define QUEUE_DEPTH 512
#define BUFFER_SIZE 1024
// 事件类型
enum EventType { ACCEPT, READ, WRITE };
// 缓冲区结构体
struct Buffer {
  char buf[BUFFER_SIZE];
  size_t length;
};

// 连接结构体
struct connection {
  int fd;                       // 文件描述
  struct sockaddr_in addr;         // 地址结构体
  char readbuffer[BUFFER_SIZE]; // 读缓冲区
  struct Buffer writebuffer;    // 写缓冲区
  enum EventType event;         // 事件类型
};

// 创建监听socket
int make_listener(const char *ip, int port) {
  // 1.创建socket
  int listen_sock = socket(AF_INET, SOCK_STREAM, 0);
  if (listen_sock == -1) {
    perror("socket");
    return -1;
  }
  // 2.构造地址结构体
  struct sockaddr_in addr;
  addr.sin_family = AF_INET;
  addr.sin_addr.s_addr = inet_addr(ip);
  addr.sin_port = htons(port);

  int opt = 1;
  if (setsockopt(listen_sock, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt)) ==
      -1) {
    perror("setsockopt");
    close(listen_sock);
    return -1;
  }
  // 3.绑定
  if (bind(listen_sock, (struct sockaddr *)&addr, sizeof(addr)) == -1) {
    perror("bind");
    close(listen_sock);
    return -1;
  }
  // 4.监听
  if (listen(listen_sock, 5) == -1) {
    perror("listen");
    close(listen_sock);
    return -1;
  }
  return listen_sock;
}

// 创建并初始化io_uring实例
struct io_uring uring_create() {
  struct io_uring ring;
  if (io_uring_queue_init(QUEUE_DEPTH, &ring, 0) < 0) {
    perror("io_uring_queue_init");
    exit(1);
  }
  return ring;
}

// 销毁io_uring实例
void uring_destroy(struct io_uring *ring) { io_uring_queue_exit(ring); }

// 提交读请求,
//  注意：调用此函数的时候，conn已经是一个准备好的新连接,fd已经被填充
bool read_request(struct io_uring *ring, struct connection *conn) {
  // 获取sqe
  struct io_uring_sqe *sqe = io_uring_get_sqe(ring);
  if (!sqe) {
    fprintf(stderr, "io_uring_get_sqe failed\n");
    return false;
  }
  // 设置事件类型为读
  conn->event = READ;
  // 准备读请求
  io_uring_prep_read(sqe, conn->fd, conn->readbuffer, BUFFER_SIZE, 0);
  // 关联用户数据，将连接结构体传递给完成队列
  io_uring_sqe_set_data(sqe, conn);
  return true;
}
// 提交写请求
//  注意：调用此函数的时候，conn已经是一个准备好的新连接,fd已经被填充
bool write_request(struct io_uring *ring, struct connection *conn) {
  struct io_uring_sqe *sqe = io_uring_get_sqe(ring);
  if (!sqe) {
    fprintf(stderr, "io_uring_get_sqe failed\n");
    return false;
  }
  conn->event = WRITE;
  io_uring_prep_write(sqe, conn->fd, conn->writebuffer.buf,
                      conn->writebuffer.length, 0);
  io_uring_sqe_set_data(sqe, conn);
  return true;
}
// 提交accept请求
//  注意：调用此函数的时候，clisten_conn已经是一个准备好的新连接,fd已经被填充
bool accept_request(struct io_uring *ring, struct connection *listen_conn) {
  struct io_uring_sqe *sqe = io_uring_get_sqe(ring);
  if (!sqe) {
    fprintf(stderr, "io_uring_get_sqe failed\n");
    return false;
  }
  listen_conn->event = ACCEPT;
  socklen_t addrlen = sizeof(listen_conn->addr);
  io_uring_prep_accept(sqe, listen_conn->fd,(struct sockaddr*)&listen_conn->addr,&addrlen,0);
  io_uring_sqe_set_data(sqe, listen_conn);
  return true;
}
// 创建连接结构体
struct connection *create_connection(int fd) {
  struct connection *conn = malloc(sizeof(struct connection));
  if (!conn) {
    perror("malloc");
    return NULL;
  }
  // 填充fd
  conn->fd = fd;
  // 初始化读写缓冲区
  memset(conn->readbuffer, 0, BUFFER_SIZE);
  memset(conn->writebuffer.buf, 0, BUFFER_SIZE);
  conn->writebuffer.length = 0;
  return conn;
}
// 处理事件循环
void handle_events(struct io_uring *ring, int listen_sock) {
  // 创建监听连接结构体
  struct connection *listen_conn = create_connection(listen_sock);
  if (!listen_conn)
    return;
  // 提交第一次accept请求,让监听连接开始接受新的连接
  accept_request(ring, listen_conn);
  // 定义完成队列事件数组
  struct io_uring_cqe *cqes[QUEUE_DEPTH];
  // 事件循环
  while (true) {
    // 提交并等待事件
    int res = io_uring_submit_and_wait(ring, 1);
    if (res < 0) {
      fprintf(stderr, "io_uring_submit_and_wait: %s\n", strerror(-res));
      break;
    }
    // 非阻塞获取完成队列事件
    int num = io_uring_peek_batch_cqe(ring, cqes, QUEUE_DEPTH);
    // 处理每个完成事件
    for (int i = 0; i < num; i++) {
      // 获取关联的连接结构体
      struct connection *conn = (struct connection *)cqes[i]->user_data;
      // 根据事件类型处理
      if (conn->event == ACCEPT) {
        if (cqes[i]->res < 0) {
          fprintf(stderr, "accept failed: %d\n", cqes[i]->res);
        } else {
          // 新连接已接受，提交读请求
          int client_fd = cqes[i]->res;
          // 创建新连接结构体
          struct connection *client_conn = create_connection(client_fd);
          // 如果创建成功，提交读请求
          if (client_conn) {
            read_request(ring, client_conn);
          } else {
            close(client_fd);
          }
          printf("Accepted new connection: ip:%s , port:%d\n", inet_ntoa(conn->addr.sin_addr), ntohs(conn->addr.sin_port));
        }
        // 继续提交accept请求，接受下一个连接
        accept_request(ring, listen_conn);
      } else if (conn->event == READ) {
        int read_bytes = cqes[i]->res;
        if (read_bytes <= 0) {
          close(conn->fd);
          free(conn);
        } else {
          // 处理读到的数据，这里简单地回显
          printf("server read : %.*s\n", read_bytes, conn->readbuffer);
          conn->writebuffer.length = read_bytes;
          memcpy(conn->writebuffer.buf, conn->readbuffer, read_bytes);
          write_request(ring, conn);
        }
      } else if (conn->event == WRITE) {
        int write_bytes = cqes[i]->res;
        if (write_bytes <= 0) {
          close(conn->fd);
          free(conn);
        } else {
          // 继续读
          read_request(ring, conn);
        }
      } else {
        fprintf(stderr, "unknown event type\n");
      }
      // 标记完成事件已处理
      io_uring_cqe_seen(ring, cqes[i]);
    }
  }
}

// 启动服务器
void start_server(const char *ip, int port) {
  // 创建监听socket
  int server_sock = make_listener(ip, port);
  if (server_sock == -1) {
    fprintf(stderr, "Failed to create listener\n");
    return;
  }
  // 创建io_uring实例
  struct io_uring ring = uring_create();
  // 处理事件循环
  handle_events(&ring, server_sock);
  // 清理
  uring_destroy(&ring);
  close(server_sock);
}

int main() {
  start_server("127.0.0.1", 8080);
  return 0;
}
```

## 四. io_uring的底层原理

### 1、 io_uring 底层原理分析

`io_uring` 的核心在于通过两个环形队列（Submission Queue, SQ 和 Completion Queue, CQ）在用户态和内核态之间传递 IO 请求和结果，从而避免了频繁的系统调用拷贝开销。

整个机制主要依赖三个核心系统调用：

#### 1. `io_uring_setup`：初始化与建环

这是一切的起点。

- **底层行为**：
     1. **参数校验**：检查 `entries`（队列大小）和 `params`（配置参数）。
     2. **创建上下文 (`io_ring_ctx_alloc`)**：在内核中分配 `io_ring_ctx` 结构体，这是管理整个 io_uring 实例的核心对象。
     3. **分配环形缓冲区 (`io_allocate_scq_urings`)**：
           - 分配 SQ 环、CQ 环以及 SQE（Submission Queue Entry）数组的内存。
           - **关键点**：这些内存是物理连续或通过 vmap 映射的，后续会被用户态 `mmap`。
     4. **初始化偏移量**：填充 `io_uring_params` 中的 `sq_off` 和 `cq_off`，告诉用户态各个指针（head, tail, ring_mask 等）在 mmap 区域的具体偏移位置。
     5. **创建文件描述符 (`io_uring_get_file`)**：分配一个匿名 inode 和文件描述符（fd），绑定 `io_uring_fops` 操作集。这个 fd 是用户态操作句柄。
- **核心结构体补充**：
     - **`io_ring_ctx`**：内核内部维护的上下文，包含所有运行时状态、锁、等待队列、io-wq（工作队列）引用等。
     - **`io_rings`**：存放 SQ 和 CQ 的头尾指针（head/tail）及数组索引的共享内存区域。

#### 2. `io_uring_register`：特性注册与优化

这是一个可选但为了高性能极其重要的调用。

- **底层行为**：
     - 通过 `__io_uring_register` 处理不同 `opcode`。
     - **缓冲区注册 (`IORING_REGISTER_BUFFERS`)**：用户态传入一组 iovec，内核通过 `pin_user_pages` 锁定这些物理页并建立映射。后续 IO 若使用这些 buffer，内核通过索引直接获取 `bvec`，**避免了每次 IO 都要进行的 `copy_from_user` 或页表查找/锁定操作**（这是传统 AIO/read/write 的一大开销）。
     - **文件注册 (`IORING_REGISTER_FILES`)**：预先打开并注册一组文件描述符。内核会在内部引用这些 file 结构体。后续提交 IO 时只需传索引，**避免了每次 IO 都要查找 fd table 获取 file 结构体并引用计数的开销**。
     - **EventFD 注册**：用于跨进程或跨线程的事件通知。

#### 3. `io_uring_enter`：提交与等待

这是数据平面的核心入口。

- **底层行为**：
     1. **提交请求 (`io_submit_sqes`)**：
           - 从 SQ 环中读取新产生的 SQE。
           - 根据 SQE 的 `opcode`（如 `IORING_OP_READV`）找到对应的处理函数（如 `io_read`）。
           - **尝试内联执行**：如果是非阻塞 IO 且资源立即可用，直接在当前系统调用上下文完成。
           - **异步下发**：如果需要阻塞（如磁盘 IO 或 socket 无数据），则将请求放入 `io-wq`（内核工作队列）或通过 poll 机制挂起。
     2. **等待完成 (`io_cqring_wait`)**：
           - 如果用户设置了 `min_complete > 0`，当前线程会睡眠，直到 CQ 环中有足够数量的 CQE。
     3. **SQPOLL 模式**：如果启用了 `IORING_SETUP_SQPOLL`，内核会启动一个内核线程（`io_sq_thread`）轮询 SQ 环。此时 `io_uring_enter` 仅用于在内核线程休眠时唤醒它，真正的数据提交完全无需系统调用。

### 2、 liburing 库的底层实现原理

`liburing` 是对上述系统调用和复杂的内存屏障/偏移量操作的封装。

1. **初始化 (`io_uring_queue_init`)**：
      - 调用 `io_uring_setup` 获取 fd 和 `io_uring_params`。
      - **mmap 映射**：根据 `params` 中的 `sq_off` 和 `cq_off`，调用 `mmap` 将内核分配的 SQ ring、CQ ring 和 SQE array 映射到用户态地址空间。
      - 设置本地 `io_uring` 结构体，保存映射后的指针（sq.khead, sq.ktail 等），方便快速访问。

2. **准备请求 (`io_uring_prep_*`)**：
      - **获取 SQE**：从 `sq.sqes` 数组中找到 `sq.tail` 对应的空闲位置。
      - **填充 SQE**：将操作码（如 `IORING_OP_READ`）、fd、buffer 地址、长度等填入 `io_uring_sqe` 结构体。
      - **注意**：此时还未通知内核，仅是在用户态修改内存。

3. **提交请求 (`io_uring_submit`)**：
      - **更新 Tail**：通过内存屏障（Write Barrier）确保 SQE 内容可见后，更新 SQ ring 的 `tail` 指针。
      - **调用 Enter**：调用 `io_uring_enter` 系统调用，通知内核“有新数据了”（`to_submit` 数量）。
      - **SQPOLL 优化**：如果开启了 SQPOLL，且内核线程在运行，`liburing` 仅需更新 tail，无需系统调用。

4. **获取结果 (`io_uring_peek_cqe` / `io_uring_wait_cqe`)**：
      - **检查 Head/Tail**：比较 CQ ring 的 `head` 和 `tail`。
      - **读取 CQE**：如果 `tail > head`，直接从映射内存中读取 `io_uring_cqe`，获取 `res`（返回值）。
      - **更新 Head**：处理完后，更新 CQ head 指针，表示该完成项已被消费。

### 3、 异步底层链路：

假设一个**异步读取磁盘文件**的场景：

1. **User (Prep)**: `liburing` 获取一个 SQE，填入 `IORING_OP_READ`，指向用户 Buffer A。
2. **User (Submit)**: 更新 SQ tail，调用 `io_uring_enter`。
3. **Kernel (Entry)**: `io_uring_enter` 被触发，锁定上下文，调用 `io_submit_sqes`。
4. **Kernel (Issue)**:
      - 读取 SQE，解析为 `io_read` 请求。
      - 获取文件对象（若已注册则直接索引，否则查表）。
      - 尝试非阻塞读取。对于磁盘文件，通常不支持非阻塞（除非是 Direct IO 且数据在缓存），因此返回 `-EAGAIN` 或直接转入异步。
5. **Kernel (Async Handoff)**:
      - 请求被加入 `io-wq` 队列。
      - 系统调用 `io_uring_enter` 返回（如果用户不等待）。
6. **Kernel (Worker Thread)**:
      - `io-wq` 的工作线程取出请求。
      - 执行真正的阻塞式 VFS 读取 (`vfs_read`)。此时只有该 Worker 线程阻塞。
7. **Kernel (Completion)**:
      - 读取完成，数据写入用户 Buffer A。
      - 构造 CQE（结果为读取字节数），写入 CQ ring。
      - 更新 CQ tail。
      - 如果用户态在 `io_uring_enter` 等待，唤醒用户进程；或者发送 `eventfd` 通知。
8. **User (Reap)**: 用户检测到 CQ ring 有数据，读取 CQE，处理数据。
