# 三种读异常

当两个事务重叠时，读者可能遇到：

- 脏读：事务回滚导致读到了不存在的值
- 不可重复读：已读取的内容发生了变化，关注记录的一致性
- 幻读：满足查询条件的纪录的集合发生了变化，关注谓词查询结果的一致性

**Postgres 不会发生脏读**：读未提交（READ UNCOMMITTED）实际可见性规则与读已提交（READ COMMITTED）相同。

# 四种隔离级别

**哪种隔离级别都挡不住更新丢失**：要么让数据库计算，要么 select for update 锁行。

以下表格描述其他事务提交的变化对当前事务的影响，不考虑当前事务读取自己的写入。

PostgreSQL 隔离级别：

| 隔离级别               | 脏读 | 不可重复读 | 幻读 | 序列化异常   |
| ---------------------- | ---- | ---------- | ---- | ------------ |
| READ UNCOMMITTED       | 不会 | 可能       | 可能 | 可能         |
| READ COMMITTED（默认） | 不会 | 可能       | 可能 | 可能         |
| REPEATABLE READ        | 不会 | 不会       | 不会 | 可能         |
| SERIALIZABLE           | 不会 | 不会       | 不会 | 不会成功提交 |

MySQL InnoDB 隔离级别：

| 隔离级别                | 脏读 | 不可重复读 | 幻读        | 序列化异常   |
| ----------------------- | ---- | ---------- | ----------- | ------------ |
| READ UNCOMMITTED        | 可能 | 可能       | 可能        | 可能         |
| READ COMMITTED          | 不会 | 可能       | 可能        | 可能         |
| REPEATABLE READ（默认） | 不会 | 不会(*)    | 通常不会(*) | 可能         |
| SERIALIZABLE            | 不会 | 不会       | 不会        | 不会成功提交 |

InnoDB 主要有哪些锁：

| 锁类型     |                           | 主要作用                               |
| ---------- | ------------------------- | -------------------------------------- |
| 共享锁     | Shared Lock（S）          | 允许多个事务读取并锁定同一记录         |
| 排他锁     | Exclusive Lock（X）       | 阻止其他事务锁定并修改对应记录         |
| 记录锁     | Record Lock               | 锁定索引中的具体记录                   |
| 间隙锁     | Gap Lock                  | 阻止向某个索引间隙插入记录（左开右闭） |
| 临键锁     | Next-Key Lock             | 记录锁 + 间隙锁                        |
| 插入意向锁 | Insert Intention Lock     | 协调多个事务在索引间隙中插入           |
| 意向共享锁 | Intention Shared（IS）    | 表明事务准备对行加 S 锁                |
| 意向排他锁 | Intention Exclusive（IX） | 表明事务准备对行加 X 锁                |
| 自增锁     | AUTO-INC Lock 协调自增 ID | 的分配                                 |
| 元数据锁   | Metadata Lock（MDL）      | 保护表结构等数据库对象元数据           |

- 意向锁用来协调表锁和行锁

# MVCC

- MVCC：负责保存和管理数据版本，并判断哪些版本对事务可见。
- 事务隔离级别：规定事务在什么时候获取快照，以及允许看到哪些数据变化。

**普通 SELECT 是快照读，SELECT FOR UPDATE/SHARE 是锁定读；在 InnoDB 中，锁定读也是当前读。**

**RC 和 RR 解决的问题不同，RC 追求读取较新的已提交数据，而 RR 追求同一事务内多次读取的一致性。**

- MySQL InnoDB 和 PostgreSQL 都采用 MVCC。普通 SELECT 在常见的 RC、RR 隔离级别下使用快照读，而锁定读和写操作需要处理并发锁冲突。
- MySQL InnoDB 更新操作通过 Undo Log 记录用于回滚和重建历史版本的信息，行记录通过回滚指针关联 Undo Log，从而形成逻辑上的版本链。RC 每次一致性读创建新的 Read View；RR 通常从第一次一致性读开始复用 Read View，直到事务结束。普通 SELECT 属于一致性读，而 SELECT FOR UPDATE/SHARE、UPDATE、DELETE 属于当前读，访问当前可用的行版本，并处理必要的锁冲突。
- PostgreSQL RC 使用语句级快照，UPDATE、DELETE、SELECT FOR UPDATE/SHARE 先根据语句快照定位目标行，如果遇到并发修改冲突，需要等待，并在对方提交后根据最新行版本重新检查条件（重新检查只发生在符合相应并发冲突条件的目标行上，不是每次 UPDATE 都必须重新检查），决定是否继续操作。RR 使用事务级快照。如果目标行在快照建立后被其他事务修改或删除并提交，当前事务尝试锁定或修改该行时会发生序列化失败，需要回滚并重试整个事务。
